# OAuth application reconnaissance rehearsal output verifier

The offline verifier checks one canonical output envelope from the
[OAuth application reconnaissance rehearsal](oauth-application-recon-rehearsal.md).
It does not invoke that pipeline or its fake four-read operation, acquire an
OAuth token, call Microsoft Graph, inspect tenant state, retry, mutate, or
persist anything.

Run one explicit local JSON output:

```sh
npm run verify:oauth-app-recon-rehearsal -- rehearsal-output.json
```

The CLI accepts exactly one regular file of at most 32 KiB. Success writes one
fixed safe summary. Refusal writes one categorical failure and exits nonzero.
Neither path echoes the input path or arbitrary input values.

## Independent verification

The verifier independently recompiles the canonical zero-cost plan and
reconstructs the categorical PR #108 adapter input: one completed workload
result and exactly four ordered reachability reads, with bounded pagination
for the two collections. It directly invokes the PR #108 adapter and PR #78
receipt verifier, recomputes the plan and fake-result digests, compares every
field with the reconstructed output, emits a stable output digest, and applies
the PR #98 shared `REHEARSAL_ONLY` envelope invariants.

The committed positive fixture is a sanitized reviewer fixture assembled from
those public contracts. It was not generated by invoking the PR #111 fake or
pipeline runner.

## Authenticated API

Operators can submit the same sanitized envelope to
`POST /api/oauth-application-recon-rehearsal-verification`. The route uses the
existing signed operator authorization before reading the body, accepts at
most 32 KiB of JSON, invokes this offline verifier synchronously in memory,
and returns at most 4 KiB of fixed summary or categorical error data. The
browser-safe typed client derives its method, path, and byte limits from the
authoritative API route registry.

This endpoint verifies supplied data only. It does not run the rehearsal,
obtain evidence, acquire a token, call OAuth or Microsoft Graph, schedule
work, persist input, or prove that external work occurred.

## Manual operator panel

The signed SPA exposes the same pure verifier through the manual-only
**Application-reconnaissance rehearsal verification** panel. The panel accepts
one sanitized PR #111 envelope, applies the authoritative 32 KiB request
parser locally before acquiring operator authorization, and calls only the
typed PR #121 client after deliberate **Verify** submission. It renders only
the fixed safe summary or categorical refusal states, suppresses duplicate
submissions and stale completions, and adds no execution, OAuth, Graph,
persistence, retry, polling, or scheduling path.

## Claim boundary

The verified summary means only that the JSON is internally consistent with
the repository contracts. Detector attribution, learner visibility and
interpretation, permission restoration, evidence-window closure, cleanup,
retention, revocation, audit completeness, tenant contents, raw identities,
external artifacts, and external impact remain `uninspected`.

Missing, duplicated, reordered, foreign, ambiguous, nonterminal, or
pagination-uncertain read categories fail closed. So do scenario, version,
plan, fake-result, receipt, envelope, or output drift; malformed or oversized
JSON; unsafe identifiers; cross-family substitution; and any external claim
promotion.
