# Private-document rehearsal output verifier

The offline verifier accepts only an exact successful output envelope from the
canonical private-document `REHEARSAL_ONLY` pipeline. It does not call that
pipeline or invoke its fake lifecycle.

Run it against one explicit PR #90 output file:

```sh
npm run verify:private-document-rehearsal -- rehearsal-output.json
```

The file must be a regular file of at most 32 KiB and use canonical two-space
JSON with one terminal newline. The CLI reads only that file and emits either a
fixed safe verification summary or a fixed categorical refusal with exit code
2. It never echoes input data or paths.

## Independent verification

For the selected synthetic branch, the verifier:

1. recompiles the canonical scenario plan and checks the scenario, manifest
   version, zero-cost plan digest, and exact output binding;
2. independently reconstructs the 30-event one-shot categorical journal:
   ordered folder/file/direct-share staging, the distinct learner observation,
   ordered permission/file/empty-folder cleanup with propagation reads, and
   producer/learner terminal observations;
3. recomputes the fake-contract digest without calling the fake lifecycle;
4. passes that reconstructed result through the PR #85 adapter; and
5. invokes the PR #78 authoritative receipt verifier.

The committed cleaned-canary and learner-observation fixtures are static
sanitized PR #90 outputs, not values generated by verifier code. They pin both
stable digests and are included in focused review.

## Claim boundary

The synthetic learner-observation branch proves only that the local adapter
contract accepts its exact learner event. The verification summary still
reports every external claim as `all-uninspected`. Producer staging, learner
visibility, interpretation, audit/detection, response, cleanup, and retention
are never promoted.

Fresh post-cleanup learner absence is terminal cleanup evidence only. It cannot
replace the earlier learner visibility observation. The cleaned-canary branch
therefore remains explicitly `synthetic-not-proven` at the visibility point
even though its separate three-round terminal state is synthetically absent.

Missing, extra, reordered, duplicated, malformed, oversized, unsafe, raw,
digest-tampered, nonterminal, cleanup-gap, branch-mismatched, or overclaiming
input fails closed. The verifier has no API route, runner or fake execution,
network access, retry, mutation, persistence, external proof, browser path, or
Windows-host dependency.
